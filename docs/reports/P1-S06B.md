## Resulting behavior and files

- `src/lib/ledger/commands/contract.ts` and `.test.ts`: strict 128 KiB JSON/Unicode/calendar/UUID/key/leg bounds, exact INR decimal parsing, frozen normalized commands, fixed-order SHA-256 v1 semantic tuple, duplicate leg preservation and golden vectors. Reason is mandatory at this raw boundary and included in hash/audit. Future consumer templates may supply controlled defaults without ordinary users typing a reason; those templates are not implemented here.
- `src/lib/ledger/commands/http.ts`: actual shared server boundary derives actor and request ID from the real verified allowlisted session, denies origin/query/internal-field attacks, maps stable private errors and emits only fixed command/status/duration/server-request-ID operational traces. Financial quantities, IDs, reasons, keys, cookies and raw errors are excluded; logging failure cannot change a committed response. Revalidates session on each attempt; replay is not an authorization credential.
- `src/lib/ledger/commands/executor.ts`: scoped SERIALIZABLE workspace authorization, receipt lookup before mutable account eligibility, deterministic distinct-account UUID locks for new posts, private draft/postings/receipt/finalization and mandatory matching audit, deferred COMMIT success before response. Immutable result projection reads only scoped journal/posting/audit data; archive/name changes cannot invalidate replay. No account metadata appears in historical DTOs.
- `src/lib/ledger/commands/retry.ts` and `.test.ts`: at most three complete attempts within a 10-second execution budget, bounded jitter, actual 40001/40P01 and named receipt-conflict handling, fresh authorization/attestation/connections/snapshots, transaction-local timeouts, safe late-connection disposal. Uncertain COMMIT connections are destroyed; no rollback/success is invented, and no new key is generated automatically.
- `src/app/api/workspaces/[id]/ledger/commands/route.ts`: actual Next adapter always supplies **null write capability**. No environment flag, request header, hosted URL or ordinary application configuration enables financial writes.
