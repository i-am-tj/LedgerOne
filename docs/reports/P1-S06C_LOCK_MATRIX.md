Relations read acquire AccessShare; SELECT FOR locks additionally acquire RowShare on locked relations; DML acquires RowExclusive on target relations and index locks, with transaction/tuple waits during conflicts. Predicate SIRead locks under SERIALIZABLE can detect conflicts without blocking; pg_locks alone does not enumerate every uncontended tuple lock. Row locks normally last until transaction end; an attempt must fully rollback/reacquire. Compatible relation modes above do not exclude DDL AccessExclusive: bounded timeouts and attestation are still required. PostgreSQL reference: [explicit locking / row modes / deadlocks](https://www.postgresql.org/docs/17/explicit-locking.html).
