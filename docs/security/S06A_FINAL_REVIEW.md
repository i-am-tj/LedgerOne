- **Tracking:** [#19](https://github.com/i-am-tj/LedgerOne/issues/19), related assurance finding [A05-03 / #15](https://github.com/i-am-tj/LedgerOne/issues/15).

- **Reproduction:** In a fresh disposable DB create non-login runtime and outsider roles. Grant ledger_account SELECT to runtime; capture with runtime mapped to RUNTIME. Execute `GRANT runtime TO outsider`. `has_table_privilege(outsider, 'ledger_account', 'SELECT')` changes false → true while the old comparator still passes. - **Impact:** Privileged provisioning could delegate financial reads without assurance detecting it. This does not give an unauthenticated application caller CREATE ROLE or establish an application isolation exploit. Runtime still has no financial DML.
- **Required correction, implemented:** Capture incoming/outgoing transitive membership edges, grantor and ADMIN/INHERIT/SET options. Normalize identity metadata only, using role names/logical identities rather than cluster OIDs; retain exact SQL bodies/literals.
- **Required regression, passed:** Direct and transitive delegation prove the outsider's effective SELECT changes and attestation fails; each membership option change fails comparison; role renames under equivalent logical aliases compare equal. Existing SQL-literal-preservation test remains green. Six added cases, full pipeline 76 integration cases.
