## Evidence record and final decision rules

Each execution artifact must record W/test ID, D-AC ID, command and exit status, source SHA and dirty state, Node/npm/PostgreSQL/OS versions, sanitized target identity/schema/role/connection mode/TLS, migration digests and applied history, reference/live catalog digest, test count and assertion output, request concurrency and observed SQLSTATE/transaction boundaries where relevant, limitations and reviewer provenance. Secrets, session cookies, idempotency keys, financial payloads and full URLs with passwords never enter reports.

The final report repeats all 15 rows with PASS or FAIL, linking the exact artifacts and scoped deferrals. Missing/NOT RUN/skipped/quarantined or wrong-profile results count as FAIL; no averaging across rows. Unexpected errors, unbalanced/unauthorized/partial/duplicate outcomes are release blockers regardless of benchmark percentiles. Capacity is a required D-AC07/W14 input, not an optional performance footnote. Gate outcome remains FAIL until every row passes and review/merge requirements are fulfilled. Technical PASS retains normal-runtime write denial and never grants activation authority.
