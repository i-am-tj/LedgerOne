## Admission and size classes

| Class          | Simultaneous commands | Proposed evidence and acceptance                                                                                                                                                                                                                                                                                                                                           |
| -------------- | --------------------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0 normal      |                     1 | Valid ordinary independent commands complete on first response. A genuine failed valid uncontended command is a defect requiring investigation. Record internal retries. Require zero unexplained first-response failures in qualification.                                                                                                                                |
| P0 overlapping |                     2 | Valid disjoint commands complete reliably within the existing budgets. Require positive first responses for the independent test fixtures. Intentional same-key replay returns the identical authorized result. Conflicting payloads and competing reversals get their specified conflict outcomes with one authorized operation. Separate these from unexpected failures. |
| P1 stress      |                     4 | Measure latency, retries, failures and recovery. Replace the previous four-way release-blocking failure-rate SLA with mandatory safety and bounded settlement/recovery. Any duplicate, partial effect, unauthorized result, unbounded request or leakage fails.                                                                                                            |
| P2 overload    |                     6 | Measure overload with the current pool sizes. Allow bounded rejection with the same safety checks as P1 and demonstrate that a new valid command completes once pressure subsides.                                                                                                                                                                                         |

A 503 counts as a failed first command attempt in every class. For serialization rollback establish the pre-recovery state, then replay the same key through fresh authorization. For ambiguous COMMIT distinguish pending, durable and absent evidence, respect settlement, and verify exactly one financial outcome. A 201 on a subsequent attempt and a 200 for an existing receipt are distinct recovery outcomes. Neither changes the original failure count.

Two through fifty legs inclusive are ordinary workloads, including the two-leg fast path for each command. Fifty-one through 500 are extended, with 50 measured as the shared boundary. Preserve maximum original/replacement of 500+500 legs, a 1,000-distinct-account union, exact amounts and duplicate multiplicity. At c1 require three independent initial 201s for every maximum positive cell with exact balances, immutable receipt, children and audit. Also require the unchanged maximum CI regression to pass. A protocol limit or timeout change needs a separate review.

## Proposed qualification manifest

1. Run deterministic accounting regressions across POST/REVERSE/CORRECT at 2/50/500 legs with small and maximal distinct unions. Include maximum quantities, duplicates, replay, cancellation, real conflicts, authorization and over-limit rejection. Test every supported length in the input-contract suite. Exercise c1/c2 positive and conflict cases, c4/c6 contention, and resource cleanup.
2. Predeclare ordinary c1/c2 measurement cells, both union sizes, cold/warm state, history and exact source/environment. Use ≥30 measured commands per representative cell. Record failures, p50/p95, first responses, attempt totals and end-to-end versus command timings. Retain command p95 ≤1 s (two legs) and ≤3 s (50 legs). Report achieved throughput. A small sample cannot establish a population reliability guarantee.
3. Proposed replacement mandatory tail cell is **two-leg POST/c2, disjoint small union**, 1,000 completed observations and command p99 ≤10 s. Preserve the original c4 series as a stress comparison. Proposed change for CORRECT50/c1 is representative p95 plus full correctness and ≥30 observations; its historical p99 stays NOT PROVEN. If the owner retains CORRECT50 as a mandatory p99 cell, insufficient observations block that criterion. Select cells before running. Include failure durations and counts; never calculate a passing p99 only from successes.
4. Separate setup, command execution, recovery and teardown clocks. Preserve the existing 240 s setup-inclusive critical-cell cap, 90 s diagnostic-cell cap and 10 min campaign cap. Predeclare independent cohorts and repeated samples. If the cap expires, record cancellations, setup failures and not-started requests and mark required p99 NOT PROVEN. Do not pool different histories, runner classes, concurrency or setup exclusions to fill the denominator.
5. Record operational acceptance independently from correctness, local versus hosted evidence and activation. All accounting/security invariants, six-writer/two-verifier pool limits, three attempts, timing bounds and private-role boundaries continue to apply. No qualification result enables normal-runtime writes.

Owners may accept or amend the class definitions and designated tail cells independently of the separate SQL proposal.
