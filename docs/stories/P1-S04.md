# P1-S04 — User-scoped authorization and audit baseline

**ID:** P1-S04 | **Title:** User-scoped authorization and audit baseline | **Epic:** P1-E2 | **Priority:** P0 | **Dependencies:** S03 implementation/live owner login, technical review `e1f6d4b`, and user's instruction to continue. No remote peer review/merge is invented.

Status: local implementation and checks PASS; awaiting review. Scope is the ownership/audit foundation, not financial account or transaction implementation.

**User story:** As an allowed user, I want my workspace and change history isolated from every other allowed user, including when IDs are guessed.

**Inputs (data/API/preconditions):** A verified current database session from S03; user-derived owner identity; optional workspace UUID; strict `{name}` JSON command (trimmed, 1–80 characters); exact configured Origin for writes. Client owner IDs and trace IDs are never authority. Audit retention default: no automatic deletion of durable mutation history before an approved privacy/export/delete policy. No financial amount input.

**Outputs (UI/API/schema/docs):** Server-only scoped services and verified-request controller; Workspace ownership container and append-only AuditEvent; migration `202611110003_ownership_audit`, schema version 3; supported APIs below; fixed-field traces and server-generated `X-Request-ID`; actual two-user DB/HTTP/browser isolation/rollback evidence. No workspace UI or financial module is presented as implemented.

| Method/path                  | Behavior                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------- |
| GET `/api/workspaces`        | Current user's workspace list, empty array until explicitly created                                     |
| POST `/api/workspaces`       | Explicitly create one workspace for current user; strict name input, 201; duplicate owner workspace 409 |
| GET `/api/workspaces/[id]`   | Owned record DTO; foreign/missing/malformed ID all return not_found 404                                 |
| PATCH `/api/workspaces/[id]` | Rename owned record with atomic audit; never reassign ownership                                         |
| GET `/api/audit`             | Current user's latest 50 immutable events, ordered by time/ID; no arbitrary owner filter                |

All responses are private/no-store. Unauthorized 401, invalid input/query 400, rejected Origin 403, missing/foreign ID 404 and dependency errors 503 are sanitized; supported owned handlers return a server trace UUID. No DELETE route exists. Empty lists and explicit success/error JSON are the applicable API states. UI remains the authenticated S02 shell; no new dead buttons or invented balances.

**Acceptance criteria (Given/When/Then):** Given two allowed authenticated users, when each lists/reads/renames a workspace or reads audit, then only its owner-derived data is accessible. Given A guesses B's UUID, when reading/writing it, then the result is identical to missing data and B's business/audit records remain unchanged. Given a successful write, when audit insertion fails, then the entire write rolls back. Given an attempted owner reassignment, cross-owner audit link or audit update/delete, when PostgreSQL executes it, then the database rejects it. Given poisoned trace headers/body or an error, when a trace is emitted, then only the server UUID, fixed route, safe method, status and duration are present.

**Failure/edge cases:** Foreign and absent IDs share 404; unknown query filters/owner fields fail closed; server IDs ignore attacker headers; anonymous/dependency errors have no business writes; duplicate creation 409; rollback retains original name/history; trace sink failure cannot change a committed response (DB audit remains transactional). Dates/UUIDs are metadata, not financial quantities. Audit DTO is latest-50 only, not a full export. No server-side auth bypass, public registration or cross-user sharing is introduced.
