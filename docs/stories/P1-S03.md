**Acceptance criteria (Given/When/Then):**

- Given missing or invalid configuration, when private pages/APIs are requested, then they deny access and login explains unavailability without exposing configuration details.
- Given a valid configured client and allowlisted verified Google account, when code/state validation succeeds, then a database-backed session is issued and private pages can render.
- Given an uninvited/unverified identity or changed returning provider identity, when the callback is processed, then it fails without unauthorized user/account/session creation.
- Given an anonymous, forged, expired, revoked or removed-from-policy session, when a private route or API is requested, then no private DTO/content is returned.
- Given a valid owner session, when logout succeeds, then the DB row and cookie are revoked, and subsequent private requests/history navigation cannot restore access in tested browsers.
- Given a cross-origin, malformed or oversized auth command, when submitted, then it fails before the library mutation; rejected logout leaves a legitimate owner session intact.
- Given OAuth state replay or absent/mismatched cookie/state, when callback is attempted, then no valid session is created.

**Rollback/migration notes:** Additive migration creates only identity/session/state/rate tables and advances schema marker 1→2. AuthAccount is not a ledger account. Do not revert to unauthenticated pages after private data is introduced. No financial posting is changed.
