**Acceptance criteria (Given/When/Then):**

1. Given a fresh database in each supported schema, when canonical commands run, then every new journal has independently specified exact legs and balances/INR assets/liabilities/net-worth/income/consumption match fixed expectations after each step.
2. Given fixed seeds and generated bounded amounts, when properties run through authenticated handlers, then accounting/replay/conflict/failure invariants hold and a failure reports schema/seed/step/input.
3. Given malicious identity/scope/session/origin/raw fields or restricted roles, when existing/new negative tests run, then access rejects with no partial side effects.
4. Given real concurrent/faulted commands, when known rollback or uncertain commit occurs, then existing bounded recovery semantics and persisted evidence hold; failures are not called successes.
5. Given a clean checkout and approved loopback control database, when verify:phase1 runs, then every mandatory stage executes or the first failure stops with nonzero exit, retained logs and exact-source/environment manifest. Cleanup never forces active connections.
6. Given green local checks but unmet original prerequisites, when the phase report is generated, then local verification may PASS while release/advancement remains BLOCKED/NOT RUN with explicit owners and evidence. No implicit Phase2/hosted/write permission.
