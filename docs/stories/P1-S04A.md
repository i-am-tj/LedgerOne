# P1-S04A — Production profiles and public entry

**ID:** P1-S04A | **Title:** Supabase production preparation and public dashboard | **Epic:** P1-E2 | **Priority:** P0 | **Dependencies:** S04 local checks; user's explicit request to pause S05 and configure Supabase, separate environments, and public entry.

**User story:** As a visitor, I can view the public foundation dashboard and enter the approved Google sign-in flow; as an owner, I reach a protected home. As the operator, local development and automated tests cannot accidentally target the hosted production database.

**Inputs (data/API/preconditions):** Existing working development credentials; user-created Supabase project linked to the selected GitHub repository; production app origin and database credentials supplied privately. Hosting is not set up yet. No public deployment, paid add-on, automatic production migration, or bank access is authorized.

**Outputs (UI/API/schema/docs):** Public `/`, protected `/home`, login transition, explicit development/production profiles, ignored private environment files and tracked templates, Supabase setup guide and guarded migration commands. Existing Prisma migration history remains authoritative; no duplicated Supabase migration files.

**Implementation tasks:**

- [x] Verify project creation/repository linkage without exposing keys.
- [x] Preserve existing local credentials in `.env.development.local`; reserve `.env` for production settings.
- [x] Guard CLI/runtime database targets, seeds and test databases; configure private production schema and verified TLS.
- [x] Add public dashboard/sign-in entry and protected home; update fixed auth destination and navigation.
- [x] Run formatting/lint/typecheck/unit/integration/build/browser checks and update traceability/evidence.
- [x] Record production prerequisites separately from verified local behavior and obtain review.

**Acceptance criteria (Given/When/Then):** Given no session, when visiting `/`, then a public preview with sign-in and no user data renders. Given a valid owner session, when visiting login, then `/home` opens. Given no valid session, when accessing `/home` or private APIs, then access is denied. Given local/test commands, when production URLs are present, then remote DB targets are rejected before connection. Given production runtime, when the database/origin/role/TLS/schema configuration is incomplete, then private access fails closed. Given a new checkout, when following the development guide, then local setup uses only dummy local DB values and no real Google credentials are needed for the public preview.

**Unit tests:** Database profile boundary, forbidden remote/local/profile combinations, production TLS/private schema/role requirements, seed and fixed auth destination regressions.

**Integration/E2E tests:** Existing real DB auth/ownership suite; desktop/mobile public dashboard, login/home transition, anonymous private denial, logout/revocation, keyboard and light/dark accessibility/reflow. Private-schema migration and restricted-role smoke rehearsal on a disposable local database. Live Supabase connectivity only after private credentials are configured.

**Failure/edge cases:** Missing production domain/credentials remains pending and is never replaced with local dummy production defaults. Public page is independent of database availability. No browser Supabase service key, no auth bypass, no public registration. Native GitHub integration does not deploy the Next.js app and does not execute Prisma migrations automatically.

**Rollback/migration notes:** No changes to existing schema migrations. Keep local credentials and DB/session history intact. Revert routing/config code together, restore callback destination and associated tests; do not reset production or rewrite migration history. Production deployment, role provisioning and migration execution require separate reviewed release evidence.

**Definition of done:** Local behavior demonstrated, environment boundaries tested, docs current, reviewable local commit and all required checks green, followed by reviewed merge. Hosted connectivity, production OAuth, backup/restore and deployment are reported as pending until actually verified. Phase 1 remains blocked on S05–S09.
