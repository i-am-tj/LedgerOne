# P1-S02 — Design system and application shell

**ID:** P1-S02 | **Title:** Design system and application shell | **Epic:** P1-E1 | **Priority:** P0 | **Dependencies:** P1-S01; user explicitly authorized advancement to S02 after making Docker available. No remote PR/merge is claimed.

Status: locally verified, awaiting review. This story adds presentation and browser-only theme preference; it does not implement authentication or financial features.

**User story:** As the owner, I want a consistent, accessible workspace that works on mobile and desktop, respects my preferred theme and explains unavailable or failed states clearly.

**Inputs (data/API/preconditions):** Approved Next.js/TypeScript/Tailwind stack; current navigation inventory; 320px minimum test width; desktop sidebar at 1024px; local theme preference; keyboard/reduced-motion requirements. No financial data or identity input.

**Outputs (UI/API/schema/docs):** Overview, Appearance and Component library routes; responsive application shell; desktop navigation/mobile dialog; light/dark/system theme; reusable Radix/shadcn-style Button/Input/Label/Card and status components; accessible form preview; real loading/error/not-found boundaries; Playwright/axe coverage and CI integration. No API/schema migration.

**Acceptance criteria (Given/When/Then):**

- Given keyboard-only navigation, when the skip link or mobile menu is used, then focus moves into main content or stays trapped in the modal, Escape dismisses it and trigger focus is restored.
- Given any supported route, when navigation is used, then the destination exists, the active route is marked and mobile navigation closes.
- Given a theme selection, when the page reloads, then the choice persists in that browser; System follows the emulated device color scheme.
- Given widths 320/768/1024 and desktop 1440, when all three routes render, then there is no horizontal page overflow; mobile controls remain usable.
- Given an invalid preview label, when submitted, then the field receives focus, an associated validation message appears and no write occurs; valid text is safely rendered in a live confirmation.
- Given loading/empty/error/success previews, when controls are used, then their visible and announced states change; retry returns to empty. The preview never implies a financial request was performed.
- Given light or dark mode, when the routes and mobile modal are scanned, then the configured WCAG A/AA axe checks report no violations.

**Unit tests:** Existing six seed-guard regressions rerun. New behavior is verified in the browser rather than duplicate shallow component tests; no financial/domain logic was added.

**Integration/E2E tests:** Existing Docker PostgreSQL readiness integration passes. `tests/e2e/shell.spec.ts` contains eight journeys across desktop/mobile Chromium (16 tests): navigation/focus trap, skip link/empty state, theme persistence/system change, form/feedback states, valid links/404, narrow reflow/reduced motion, and light/dark accessibility/visual evidence. `npm run test:e2e` starts the production build on loopback port 3100 and closes it afterward; run `npm run build` first. CI builds before running browsers and uploads reports/screenshots/traces for seven days.

**Failure/edge cases:** Empty product data; unavailable modules; invalid/long label; HTML-like text rendered as text; route miss; theme reload and system change; narrow viewport; modal Escape/Tab cycle; reduced motion. Route error/loading components share tested feedback primitives; injecting an actual server render failure was not part of this story. Automated axe checks and screenshot review do not establish universal accessibility conformance or replace screen-reader assessment.

**Rollback/migration notes:** No database or financial migration. Revert this story's presentation/components/test configuration if necessary, retaining the prior platform migration. The only added persistence is the non-sensitive `ledgerone-theme` localStorage key, safely ignored by the previous scaffold. No posted data is modified.

**Definition of done:** Demonstrated behavior, all required checks green, no fake data/actions, documented accessibility states and limitations, updated traceability, safe UI-only rollback and reviewed merge. Current state is ready for review; no review/merge is invented.
