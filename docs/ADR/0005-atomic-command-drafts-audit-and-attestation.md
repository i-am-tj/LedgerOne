# ADR-005 — Private command drafts, scoped audit and invariant attestation

Date: 2026-11-11. Story: P1-S06A. Status: implemented locally; current-head human accounting/security review and reviewed merge pending. S05 owner review/merge is confirmed separately; it does not approve this change automatically.

S06 commands will construct drafts privately inside one transaction from a strict validated command. No stored editable-draft finalization endpoint is exposed. The current child-edit revision is not a full draft version; rejecting draft IDs/revisions and hash-conflicting semantic payloads is required in S06B/C. A future editable-draft feature must reopen A05-01 with complete version protection. This selects one option expressly allowed by the user's S06 scope, not an assertion that version coverage was fixed.

Migration 007 adds nullable financial audit context for legacy compatibility and scoped operation/target foreign keys. Financial action/reason are constrained and one financial audit per operation is allowed. Deferred validation requires the exact posted target and matching operation kind. Existing workspace events remain valid and all audit events stay append-only. Existing receipts/raw SQL fixtures are not retrospectively declared audited: mandatory command audit insertion and rollback through actual handlers remains S06B/C. No write API or runtime DML permission is added by these schema capabilities.

A CORRECT receipt must not reverse a journal in its own operation. The new SQL defense is in addition to S06C's required explicit authorized original selection/locking; it does not replace service authorization or guarantee correction intent on its own. Full opposite posting multiset, single full reversal, immutable originals, acyclic posted predecessor and archive restrictions remain unchanged.

Prisma diff and migration checksums cannot prove live SQL accounting protection. The verifier compares a target's consistent catalog/migration snapshot against a fresh reviewed migration reference, including checks, enabled triggers, function source/security/search paths, ownership/grants, columns/indexes/enums and configured role metadata. Same-schema/profile comparison is intentional; role aliases apply only to identity/ACL metadata. SQL source and literals are never globally rewritten during comparison. Unknown/empty/mismatched/unavailable state fails closed. It is not a defense against a malicious migration/deployment administrator controlling both source and database.

The current operator CLI is guarded local-test/public-schema only; it validates the test profile before connection and redacts failure output. Hosted/private production attestation needs a separately reviewed reference/provisioning profile and authorization. Private-schema rehearsal verifies local role/audit portability and detects temporary privilege broadening; it is not hosted Supabase proof. Future financial exposure must integrate attestation and restricted role permissions under S06D. Financial runtime grants remain SELECT-only and the INR-only FX gate stays enforced.

Migrations are additive and checksum-safe: 001–006 are untouched, 007 is preserved after local application, readiness advances to 7. Recovery is disable exposure/forward repair with retained immutable evidence; do not edit applied SQL, erase receipts or drop balances. No production migration or restore test is claimed. The S06 write gate remains NOT RUN/FAIL until real handler authorization, canonical idempotency, mandatory audit, correction and serialization/deadlock retry scenarios pass and receive review.
